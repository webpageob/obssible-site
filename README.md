# 이 사이트 운영법

6개월 뒤에 봐도 알 수 있게 순서대로 적는다.

## 새 글 하나 올리기 (전체 과정)

**1. `posts/` 폴더에 마크다운 파일을 하나 만든다.**

파일 이름은 아무거나 상관없다. `아무이름.md` 도 되고 `2026-08-05-제목.md` 도 된다. 실제 웹 주소는 파일 이름이 아니라 2번의 `slug:` 값으로 정해진다.

**2. 맨 위에 이 세 줄을 넣는다.**

```
---
title: 글 제목
date: 2026-08-05
slug: 원하는-주소
---
```

- `title` — 페이지 제목으로 쓰인다
- `date` — 목록 정렬 기준(최신순)이자 화면에 보이는 날짜
- `slug` — 웹 주소가 된다. 예를 들어 `slug: my-first-log` 라고 쓰면 그 글은 `obssible.com/log/my-first-log.html` 이 된다. **영어 소문자와 하이픈(`-`)만 쓰는 걸 권장** — 한글이나 띄어쓰기가 주소에 들어가면 지저분해진다

**3. 그 아래에 본문을 마크다운으로 쓴다.**

지원하는 문법은 이게 전부다:

| 쓰면 | 이렇게 변환됨 |
|---|---|
| `## 소제목` | 소제목 |
| 그냥 줄글 | 문단 |
| `- 항목` | 목록 |
| `> 인용문` | 인용문 |
| `` `코드` `` | 코드체 |
| `**굵게**` | 굵게 |
| `*기울임*` | 기울임 |
| `[글자](주소)` | 링크 |

표, 이미지, 번호 매긴 목록은 아직 지원 안 한다.

**4. 터미널에서 `site` 폴더로 이동해서 이 명령을 친다.**

```bash
python build.py
```

**5. 이 한 줄이 자동으로 다 처리하는 일:**

- `log/원하는-주소.html` — 글 페이지를 새로 만든다
- `log/index.html` — 전체 글 목록을 다시 만든다 (새 글이 날짜순 맨 위에 온다)
- `rss.xml` — RSS 피드를 다시 만든다 (Buttondown이 이걸 읽고 이메일을 자동 발송한다)
- `index.html` (홈 화면) — 상단 메뉴와 "최신 글" 미리보기를 갱신한다

**6. 결과를 확인한다.**

```bash
python -m http.server 4173
```

띄운 다음 브라우저에서 `localhost:4173` 열어서 확인.

**7. 문제없으면 GitHub에 올린다.**

```bash
git add -A
git commit -m "새 로그: 제목"
git push
```

push하면 Netlify가 자동으로 감지해서 몇 십 초 안에 `obssible.com`에 그대로 반영한다. **더 이상 Netlify 화면에 폴더를 끌어다 놓을 필요 없다.**

## 글 고치기

`posts/` 안의 `.md` 파일을 고치고 `python build.py` 다시 실행. 끝.

## 글 지우기

`posts/` 안의 `.md` 파일을 지우고 `python build.py` 다시 실행하면, `log/`에 있던 그 글의 페이지도 **자동으로 같이 지워진다.**

## 글 주소(slug) 바꾸기

프런트매터의 `slug:` 값만 새 값으로 고치고 `python build.py` 실행. 옛날 주소의 파일은 자동으로 지워지고 새 주소로 다시 생긴다. (단, 그 글 링크를 어딘가에 이미 공유했다면 옛날 링크는 깨진다 — 자주 바꾸지 않는 게 좋다.)

## 손으로 고치는 파일 vs 자동 생성되는 파일

| 파일 | 누가 고치나 |
|---|---|
| `posts/*.md` | **여기가 진짜 원본이다.** 글은 여기서만 쓴다 |
| `index.html` | 직접 고친다. 단 `<!-- NAV:START -->`와 `<!-- LATEST:START -->` 사이 두 구간은 build.py가 매번 덮어씀 |
| `about.html` | 직접 고친다. 단 `<!-- NAV:START -->` 구간은 build.py가 덮어씀 |
| `log/index.html` | **손대지 마라.** 매번 통째로 새로 만들어진다 |
| `log/*.html` (글 각각) | **손대지 마라.** 원본은 `posts/`에 있다 |
| `rss.xml` | **손대지 마라.** 매번 통째로 새로 만들어진다 |
| `partials/nav.html` | 메뉴 항목을 바꾸고 싶을 때 여기를 고친다 |
| `assets/style.css` | 사이트 전체 디자인(색·글꼴·여백)이 전부 여기 한 파일에 있다. 모든 페이지(`index.html` 포함)가 이 파일을 불러 쓴다 |
| `build.py` | 웬만하면 안 건드린다 |

## 주의 — NAV/LATEST 표시가 사라지면

`index.html`이나 `about.html`을 다른 도구(디자인 툴, 다른 세션 등)로 통째로 다시 만지면, 그 안의 `<!-- NAV:START -->` 같은 주석이 같이 지워질 수 있다. 이 주석이 없으면 `build.py`를 돌려도 그 파일의 메뉴·최신글이 더 이상 자동으로 안 바뀐다.

**확인법:** `python build.py` 를 실행했을 때 터미널에 `⚠ marker ... not found` 라는 줄이 뜨면 그 신호다. 그러면 해당 파일에서 메뉴/최신글 부분을 찾아 앞뒤로 이 주석을 다시 감싸주면 된다:

```html
<!-- NAV:START -->
(메뉴 html)
<!-- NAV:END -->
```

```html
<!-- LATEST:START -->
(최신 글 미리보기 html)
<!-- LATEST:END -->
```

## RSS → Buttondown 자동 발송 연결법 (나중에 할 일)

`rss.xml`은 Buttondown이 읽고 이메일을 자동으로 보낼 수 있는 형식으로 만들어져 있다. 연결 방법:

1. Buttondown 관리 화면 → **Automations** (또는 RSS 관련 메뉴) 로 들어간다
2. 피드 주소로 `https://obssible.com/rss.xml` 을 등록한다
3. Buttondown은 **30분마다** 이 주소를 확인해서, 그동안 못 봤던 새 글이 있으면 자동으로 이메일을 만든다
4. 새 글을 구분하는 기준은 `<guid>` 값(=글 주소)이다. 그래서 **한 번 발송된 글의 slug는 절대 재사용하지 마라** — 같은 slug로 다시 쓰면 Buttondown이 "이미 보낸 글"로 착각해서 다시 안 보낼 수 있다

즉, 새 글 올리는 절차(위 1~7번)는 그대로고, `python build.py` 실행 → 배포 두 가지만 끝내면 그다음은 Buttondown이 알아서 이메일을 보낸다. 이 사이트에서 따로 발송 버튼을 누를 일은 없다.

## 배포 — GitHub과 Netlify가 자동으로 연결돼 있다

`site` 폴더는 GitHub 저장소(`webpageob/obssible-site`)와 연결돼 있고, 그 저장소는 Netlify와 연결돼 있다. **`git push` 한 줄이 곧 배포다.**

```
python build.py   (내 컴퓨터에서 HTML·RSS 생성)
      ↓
git push          (GitHub에 올리기)
      ↓
Netlify가 자동 감지 → obssible.com 갱신 (몇 십 초 안에)
```

Netlify 화면에 폴더를 직접 끌어다 놓는 옛날 방식은 이제 안 쓴다.
